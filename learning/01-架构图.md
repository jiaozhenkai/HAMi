# 架构图

## 一、整体架构总览

HAMi 通过扩展 Kubernetes 调度器 + 设备插件 + 容器内拦截三层机制，实现 GPU/NPU 等加速器的虚拟化共享与隔离。

```mermaid
graph TB
    subgraph K8s["Kubernetes 集群"]
        API["kube-apiserver"]

        subgraph ControlPlane["控制面"]
            WH["MutatingWebhook<br/>(hami-scheduler 内)"]
            KSC["kube-scheduler<br/>(标准调度器 + extender)"]
            SE["HAMi Scheduler Extender<br/>cmd/scheduler<br/>:8080/:443"]
        end

        subgraph Node["GPU 节点 (DaemonSet)"]
            Kubelet["kubelet"]
            DP["HAMi Device Plugin<br/>cmd/device-plugin/nvidia<br/>(gRPC → kubelet)"]
            VM["HAMi vGPU Monitor<br/>cmd/vGPUmonitor<br/>:9394/metrics"]
            LIB["libvgpu.so<br/>(注入到每个容器)"]
        end
    end

    User["用户 Pod<br/>nvidia.com/gpu: 1"]


    User -->|1. kubectl apply| API
    API -->|2. Admission| WH
    WH -->|3. 注入 schedulerName + 默认资源| API
    API -->|4. 调度| KSC
    KSC -->|5. filter/score/bind| SE
    SE -->|6. 读取节点设备注解| API
    SE -->|7. 写入设备分配注解到 Pod| API
    API -->|8. Pod 绑定到节点| Kubelet
    Kubelet -->|9. Allocate 请求| DP
    DP -->|10. 读取 Pod 注解<br/>注入环境变量/挂载 libvgpu.so| Kubelet
    Kubelet -->|11. 启动容器| LIB
    VM -->|12. 读取共享内存<br/>监控+限制 GPU 使用| LIB
    VM -->|13. Prometheus :9394| Prom["Prometheus / Grafana"]
    SE -.->|metrics :9395| Prom

    style SE fill:#4A90D9,color:#fff
    style DP fill:#50C878,color:#fff
    style VM fill:#F5A623,color:#fff
    style LIB fill:#BD10E0,color:#fff
    style WH fill:#D0021B,color:#fff
```

## 二、三大组件部署形态

HAMi 通过 Helm Chart（`charts/hami/`）部署，三个组件以不同方式运行：

```mermaid
graph LR
    subgraph SchedulerDeployment["Deployment (hami-scheduler)"]
        S1["kube-scheduler 容器<br/>(可选, 标准 K8s 调度器)"]
        S2["vgpu-schedule-extender 容器<br/>(HAMi scheduler 二进制)"]
        S1 <-->|extender 配置| S2
    end

    subgraph DevicePluginDS["DaemonSet (hami-device-plugin)"]
        D1["device-plugin 容器<br/>(nvidia-device-plugin 二进制)<br/>postStart: 安装 vgpu-init.sh"]
        D2["vgpu-monitor 容器<br/>(vGPUmonitor 二进制)"]
        D1 -.->|共享卷| D2
    end

    SVC1["Service<br/>NodePort 31998→443<br/>NodePort 31993→9395"]
    SVC2["Service<br/>NodePort 31992→9394"]
    WHC["MutatingWebhookConfiguration<br/>vgpu.hami.io"]

    S2 --> SVC1
    D2 --> SVC2
    WHC --> S2

    style S2 fill:#4A90D9,color:#fff
    style D1 fill:#50C878,color:#fff
    style D2 fill:#F5A623,color:#fff
```

| 组件 | 工作负载类型 | 主要容器 | 端口 | 副本 |
|------|------------|---------|------|------|
| Scheduler Extender | Deployment | kube-scheduler + vgpu-schedule-extender | 443/80 (调度), 9395 (metrics) | 1（可开主备选举） |
| Device Plugin | DaemonSet | device-plugin + vgpu-monitor | gRPC (kubelet socket), 9394 (metrics) | 每个GPU节点 1 个 |
| Webhook | 嵌入 Scheduler | — | 443 | 与 scheduler 同生命周期 |

## 五、设备抽象层架构

HAMi 的核心设计是**设备后端插件化**，所有硬件厂商实现统一的 `Devices` 接口：

```mermaid
graph TD
    DI["Devices 接口 (pkg/device/devices.go)<br/>13 个方法"]

    DI2["Core 生命周期方法:<br/>• CommonWord() — 设备类型标识<br/>• MutateAdmission() — Webhook 变更<br/>• CheckHealth() — 健康检查<br/>• NodeCleanUp() — 节点清理"]
    DI3["资源发现方法:<br/>• GetResourceNames() — K8s 资源名<br/>• GetNodeDevices() — 读取节点设备清单<br/>• GenerateResourceRequests() — 解析容器请求"]
    DI4["调度核心方法:<br/>• Fit() — 设备能否满足请求<br/>• ScoreNode() — 节点评分<br/>• AddResourceUsage() — 记录分配"]
```

### 设备注册流程

```mermaid
sequenceDiagram
    participant Main as "cmd/scheduler/main.go"
    participant Config as "config.InitDevicesWithConfig()"
    participant DM as "device.DevicesMap"
    participant Backend as "各设备后端 Init*Device()"

    Main->>Config: 启动时调用
    Config->>Config: 1. 读取 YAML 配置文件
    Config->>Config: 2. 重置 DevicesMap 和 DevicesToHandle
    Config->>Config: 3. 构建 deviceInitializers 列表 (16 个后端)
    loop 每个后端
        Config->>Backend: 4. 调用 Init*Device(config) 返回 Devices 实现
        Backend-->>Config: 返回设备对象
        Config->>DM: 5. DevicesMap[commonWord] = dev
        Config->>Config: 6. DevicesToHandle = append(...)
    end
    Note over Config: Ascend/Iluvatar 返回 []Devices (多芯片)
    Config-->>Main: 完成，全局 DevicesMap 就绪
```
